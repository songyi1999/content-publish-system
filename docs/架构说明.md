# 架构说明

## 总体

```
┌─────────────┐   HTTPS/REST    ┌───────────────────────────────┐
│  管理后台     │ ──────────────▶ │  服务端 NestJS（B/S）            │
│  admin-web   │ ◀────────────── │  apps/server                  │
└─────────────┘                 │  ├─ REST API（/api）            │
                                │  ├─ socket.io /device 设备网关    │
┌─────────────┐   WebSocket     │  ├─ /media 静态媒体（本地磁盘）     │
│  终端客户端   │ ◀──────────────▶ │  └─ BullMQ 定时/下发队列（M4+）   │
│ APK / EXE    │   HTTP 断点续传   │          │                     │
│ player-core  │ ──────────────▶ └──────────┼─────────────────────┘
└─────────────┘                            ▼
                              PostgreSQL 16 │ Redis 7（全部容器化）
```

## 关键设计

### 1. 共享播放器内核（单人维护双端的核心）

`packages/player-core` 是纯 TS 包，不依赖任何平台 API：

- `scheduler.ts`：排期冲突与分时段判定（R12）。输入排期数组 + 当前时间，输出应播节目；无生效排期返回 null，由调用方回落默认节目单（不黑屏）。
- `playlist.ts`：节目内条目循环定位（时长加权取模）。
- `store.ts`：`ContentStore` 接口 —— 终端离线内容库抽象（R2）。Android 用 capacitor-sqlite 实现、Windows 用 better-sqlite3 实现，M5 里程碑接入。

### 2. 通信协议（packages/shared）

- 设备侧：`device:hello` / `device:heartbeat`（默认 30 秒）/ `device:command`（publish、unpublish、reboot、screenshot、shutdown…）/ `device:result`。
- 指令带 `issuedAt` 时间戳，终端侧防重放（M4 实现）。
- 内容状态机 `CONTENT_TRANSITIONS`：发布仅可从 APPROVED 触发，编辑-审核-发布职责分离（R6）在类型层即受约束。

### 3. 媒体存储

本地磁盘直写（`StorageService`，根目录 `MEDIA_ROOT`，容器挂载卷），对外经 `/media` 前缀暴露；下载走 Nginx 反代 + `Accept-Ranges`（M4 实现断点续传）。保留薄接口便于未来切换对象存储。

### 4. 容器化

- 开发：`docker-compose.dev.yml` 仅起 PostgreSQL + Redis，代码本机热更。
- 部署：`docker-compose.yml` 四容器（pg/redis/server/admin-web），server 镜像内置 ffmpeg 支撑转码（M3）。
- CI 产镜像推 GHCR（`server-docker.yml`）。

### 5. 模块与数据模型

`apps/server/prisma/schema.prisma`：Role/User（RBAC）、ColumnNode（栏目树）、MediaAsset、Content（状态机）、DeviceGroup/Device（激活码、心跳、电源策略）、PublishTask、Schedule（排期优先级）、AuditLog（追加审计）。

## 技术风险与预案

| 风险 | 预案 |
|---|---|
| Capacitor 自启/保活受厂商 ROM 限制（R10 最大风险） | M5 初真机验证；不满足则自写原生插件（BootReceiver + 前台服务，约百行 Java） |
| Electron 体积与首启速度 | 播放器为轻量 Vue 页面，无重依赖；接受体积换取与 Web 复用 |
| 单人串行导致集成晚 | M5 即出真机闭环；每里程碑有可演示版本 |
