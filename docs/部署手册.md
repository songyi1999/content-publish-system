# 部署手册（容器化）

## 一、首次部署

```bash
git clone <仓库地址> && cd content-publish-system
cp .env.example .env
# 编辑 .env：修改 POSTGRES_PASSWORD、JWT_SECRET（openssl rand -hex 32）
docker compose up -d --build
```

启动后：

- 管理后台：`http://<主机IP>:8080`（初始账号 admin / admin123，**登录后立即修改**）
- 服务端 API：`http://<主机IP>:3000/api/health`（健康检查）
- 数据库：容器卷 `cps-pgdata`；媒体：宿主机 `./data/media`（随仓库目录，注意备份）

数据库迁移在 server 容器启动时自动执行（`prisma migrate deploy`）。种子账号：

```bash
docker compose exec server pnpm --filter @cps/server exec prisma db seed
```

## 二、日常升级

```bash
git pull
docker compose build server admin-web
docker compose up -d
```

或使用 CI 镜像：修改 compose 中 server/admin-web 的 `build:` 为 `image: ghcr.io/<org>/<repo>/cps-server:latest` 后 `docker compose pull && docker compose up -d`。

## 三、备份与恢复

```bash
# 备份（建议 crontab 每日）
docker compose exec -T postgres pg_dump -U cps cps | gzip > backup/cps-$(date +%F).sql.gz
tar czf backup/media-$(date +%F).tar.gz data/media

# 恢复
gunzip -c backup/cps-YYYY-MM-DD.sql.gz | docker compose exec -T postgres psql -U cps cps
```

## 四、终端接入

1. 管理后台 → 设备管理 → 新建设备，获得**激活码**。
2. 终端安装 APK/EXE（GitHub Releases 下载），首次启动输入激活码完成注册绑定。
3. 后台按分组下发内容；终端下载后本地缓存离线播放。

## 五、常用排查

| 症状 | 检查 |
|---|---|
| 后台打不开 | `docker compose ps`；`docker compose logs admin-web` |
| 登录报数据库错误 | `docker compose logs server`；检查 postgres 健康状态 |
| 终端一直离线 | 终端与服务端网络可达性；`docker compose logs server \| grep terminal` |
| 媒体无法预览 | `./data/media` 权限；Nginx `/media` 反代配置 |

## 六、慢网环境说明

国内网络拉取 Docker Hub（mwader/static-ffmpeg、node 等）或 Debian 源较慢时：
1. 先单独预拉：docker pull mwader/static-ffmpeg:7.1、docker pull node:20-bookworm-slim；
2. 或在 Docker Desktop 配置可用的镜像加速器；
3. 直接使用 CI 产物：GitHub Actions Server Docker Images 推送到 ghcr.io 后，修改 compose 的 image 字段拉取即可，无需本地构建。
